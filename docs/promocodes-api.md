# Промокоды API

Все запросы используют cookie-сессию сайта. Коды нормализуются в верхний регистр и допускают 2–40 букв, цифр, `-` и `_`. Уникальность действует в пределах повара; одинаковые коды у разных поваров допустимы, но в корзине с товарами обоих владельцев такой код считается неоднозначным и отклоняется.

## `GET /api/promocodes.php`

Только авторизованный повар. Возвращает только его активные коды:

```json
{"success":true,"promocodes":[{"id":12,"code":"SUMMER","discount_percent":10}]}
```

## `POST /api/promocodes.php`

JSON-действия:

- Создание: `{"action":"create","code":"SUMMER","discount_percent":10}`
- Изменение: `{"action":"update","id":12,"code":"SUMMER","discount_percent":15}`
- Удаление: `{"action":"delete","id":12}`

Все операции ограничены `cook_id` из сессии. Повтор кода того же повара возвращает `409`; объект другого повара недоступен и отвечает как не найденный.

## `POST /api/validate_promocode.php`

JSON: `{"code":"SUMMER","items":[{"id":42,"qty":2}]}`

Цены, владельцы и доступность блюд берутся только из БД. Успешный ответ содержит код, владельца, процент, сумму блюд владельца и скидку в рублях. Скидка не распространяется на блюда других поваров. Ошибки проверки возвращают понятное поле `error` и HTTP `422`.

## `POST /api/create_order.php`

В существующий запрос добавляются `promocodes` — массив кодов и необязательные координаты выбранной точки доставки:

```json
{"items":[{"id":42,"qty":2}],"payment_method":"Карта","delivery_address":"Москва, ул. Примерная, 1","delivery_lat":55.7558,"delivery_lng":37.6173,"promocodes":["SUMMER","CHEF-5"]}
```

Перед созданием заказа сервер повторно проверяет доступность блюд, владельцев и коды в транзакции. Разрешён максимум один код каждого повара. Сумма заказа строк после скидки сохраняется в `orders.total_price`; округление распределяется между строками, чтобы итог точно совпал со скидкой. Ответ включает `discount_amount` и `applied_promocodes`.
Если переданы допустимые координаты, они сохраняются вместе с адресом в `orders.delivery_address`, поскольку в текущей схеме заказов нет отдельных полей широты и долготы. Выбранный адрес заказа не меняет адрес профиля покупателя.
